# Multi-tenancy + RLS (pool model)

## Model
Tenant = isolation boundary (RLS). Branch = operational boundary (app + optional RLS). Catalogs shared across branches use `branch_id NULL`.

## Table template (every tenant-owned table)
```sql
CREATE TABLE things (
  id uuid PRIMARY KEY,                           -- UUIDv7 generated by the app (native uuidv7() only exists in PG 18+)
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  branch_id uuid REFERENCES branches(id),        -- NULL = all branches (only if shared)
  -- ...columns...
  attrs jsonb NOT NULL DEFAULT '{}',
  version int NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(), created_by uuid,
  updated_at timestamptz, updated_by uuid
);
CREATE INDEX things_tenant_idx ON things (tenant_id, branch_id /*, hot columns */);
SELECT app.enable_tenant_rls('things');          -- helper below
```
```sql
CREATE FUNCTION app.tenant_id() RETURNS uuid LANGUAGE sql STABLE AS
$$ SELECT nullif(current_setting('app.tenant_id', true), '')::uuid $$;
CREATE FUNCTION app.branch_ids() RETURNS uuid[] LANGUAGE sql STABLE AS
$$ SELECT nullif(current_setting('app.branch_ids', true), '')::uuid[] $$;  -- NULL = all

CREATE FUNCTION app.enable_tenant_rls(t regclass) RETURNS void LANGUAGE plpgsql AS $$
BEGIN
  EXECUTE format('ALTER TABLE %s ENABLE ROW LEVEL SECURITY', t);
  EXECUTE format('ALTER TABLE %s FORCE ROW LEVEL SECURITY', t);
  EXECUTE format($p$CREATE POLICY tenant_isolation ON %s
     USING (tenant_id = app.tenant_id()) WITH CHECK (tenant_id = app.tenant_id())$p$, t);
END $$;
```
Optional extra policy for sensitive tables (vouchers, gl_entries, cash):
```sql
CREATE POLICY branch_scope ON gl_entries AS RESTRICTIVE
  USING (app.branch_ids() IS NULL OR branch_id = ANY (app.branch_ids()));
```

## Rules
- `ENABLE` **and** `FORCE`; policies always have `USING` **and** `WITH CHECK`.
- `tenant_id` is the **leading** column of indexes; unique constraints are scoped `(tenant_id, ...)` or `(branch_id, ...)`.
- Context is **transaction-local**: `SELECT set_config('app.tenant_id', $1, true)` (works with PgBouncer transaction pooling). Unset => NULL => zero rows (fail closed).
- App role `innkeeper_app` is `NOBYPASSRLS` and not the table owner. Migrations use `innkeeper_owner`. Never use a superuser/BYPASSRLS role in request paths.
- Global tables (no RLS): `tenants`, `users` (identity), plan/feature catalogs, system templates. Access them only through a narrow, audited auth/platform service.
- Jobs, outbox consumers, SSE: every dispatcher opens a `RequestContext` with the event's `tenantId`; no tenant-less queries.
- FKs across tenants must be impossible: use composite FKs `(tenant_id, parent_id) -> parent(tenant_id, id)` for high-risk relations, or validate in use cases + leakage tests.

## Request flow
1. Resolve tenant (subdomain) -> verify JWT `tid` matches.
2. Verify `X-Branch-Id` is in membership scope (or `ALL`).
3. `TenantTransactionInterceptor`: `BEGIN` -> `set_config('app.tenant_id'|'app.branch_ids', ..., true)` -> run use case -> `COMMIT`.
4. Repos accept only the transactional handle (lint-enforced). No `pool.query` in modules.

## Leakage test (required for every new table)
```ts
for (const table of tenantTables) {
  it(`${table}: tenant A cannot read/update/delete/insert tenant B rows`, async () => {
    await seedRow(table, tenantB);
    await asTenant(tenantA, async (db) => {
      expect(await db.selectFrom(table).selectAll().execute()).toHaveLength(0);
      expect((await db.updateTable(table).set({ updated_by: x }).executeTakeFirst()).numUpdatedRows).toBe(0n);
      expect((await db.deleteFrom(table).executeTakeFirst()).numDeletedRows).toBe(0n);
      await expect(insertRowFor(table, tenantB)).rejects.toThrow(/row-level security/);
    });
    await asNoTenant(async (db) => expect(await db.selectFrom(table).selectAll().execute()).toHaveLength(0));
  });
}
```
The list of tables is discovered from `pg_class` where `relrowsecurity` is expected: a table with a `tenant_id` column but **without** RLS fails CI.

## Common mistakes
- Forgetting `WITH CHECK` (tenant can re-parent rows). - Using `SET` instead of `set_config(..., true)` (leaks across pooled connections). - Reporting/analytics role bypassing RLS without audit. - Caching data without tenant in the cache key. - SSE/WebSocket fan-out not filtering by tenant+branch. - Seeding scripts run as owner that forget `tenant_id`.

## Upgrade path
All DB access goes through `TenantDbRouter(tenantId) -> pool`. Default returns shared pool; large tenants may be mapped to a dedicated database (silo) without code changes.
